Privacy

Your tests stay in your browser

No account and no analytics. Here is what Pocket QA keeps, the one request it makes, and why it asks for each permission.

  • Stored on this computer. Scenarios, variables, CSV data, screenshots and run results live in Chrome's local extension storage. Nothing is uploaded.
  • Settings can sync. Hotkeys, screenshot naming and notification switches use Chrome's sync storage, so they follow you to your other devices if Chrome Sync is on.
  • One request out, once a day. Alongside Chrome's own update check, Pocket QA reads a small version file from kt-hg.github.io so a broken release can be stopped. The request carries none of your data.
  • DB rollback stays on your Adminer. Undo SQL goes only to the Adminer page you are working in, over your existing session.

FAQ

Is Pocket QA free?

Yes, completely — no paid tier and no account.

Do I need to write code?

No. Record a flow once and replay it from the popup. Code export is there for when you want the same test in Selenium, Playwright, Robot Framework or Java.

Which browsers does it run on?

Chrome 109 or newer.

Why does Chrome say Pocket QA "started debugging this browser"?

Chrome shows that bar whenever an extension uses its debugger API, which Pocket QA does for the steps listed under debugger above. It detaches when the run ends, and the bar goes away.
